# Admin Web Design

## Goal

为仓库新增一个独立的管理员前端项目 `bilibili_admin_web/`，用于管理员登录、视频管理、用户管理入口。第一阶段先完成最小前端骨架与页面结构，不改动后端代码。

## Scope

本次设计覆盖：

- 独立管理员前端项目目录
- 管理员登录页
- 视频管理页结构
- 用户管理页占位结构
- 管理员端路由、导航、登录态与权限拦截

本次不覆盖：

- 后端管理员用户管理接口实现
- 视频状态筛选接口实现
- 用户管理真实数据接入

## Architecture

管理员端采用独立前端项目，不混入现有 `bilibili_web/`。项目使用与现有前端一致的技术方向，便于复用心智模型和接口调用方式，但登录态与路由隔离，避免与普通用户前端互相污染。

管理员端页面结构如下：

- `/login`：管理员登录页
- `/videos`：视频管理页，登录后的默认首页
- `/users`：用户管理页，占位页

整体布局采用左侧导航，导航项固定为：

- 视频管理
- 用户管理
- 退出登录

## Login And Auth

管理员登录复用现有 `/users/login` 接口。

登录成功后前端读取返回的 `roleCode`：

- `ADMIN`：允许进入后台
- 非 `ADMIN`：停留在登录页，并提示“没有管理员权限”

管理员端本地存储单独命名，不直接复用普通前端的登录存储键，避免两个前端互相覆盖 token 或用户信息。

路由守卫规则：

- 未登录访问 `/videos` 或 `/users` 时，跳转 `/login`
- 已登录管理员访问根路径时，跳转 `/videos`
- 接口返回 `401` 或 `403` 时，清空管理员登录态并返回 `/login`

## Video Management

视频管理页是管理员端默认首页。

第一版列表字段固定为：

- 封面
- 标题
- 投稿人
- 投稿时间
- 时长
- 当前状态
- 操作按钮

页面结构：

- 顶部状态标签：`待审核`、`已通过`、`已拒绝`
- 中部视频列表
- 右侧审核抽屉

审核交互采用“列表 + 右侧抽屉”：

- 列表中点击“查看审核”或“查看详情”
- 右侧打开抽屉
- 抽屉展示封面、标题、作者、简介、时长、投稿时间、视频地址
- 对于待审核视频，显示“通过”“拒绝”操作
- 对于已通过或已拒绝视频，仅展示状态，不重复审核

前端结构先按三种状态切换设计，但当前后端现状仅明确提供待审核列表与审核状态更新接口，因此第一阶段以前端骨架和交互结构为主，不要求三种状态都已接上真实数据。

## User Management

用户管理页第一版仅做正式页面占位，不接管理员真实接口。

页面保留未来能力入口，但标记为暂未接入：

- 搜索用户
- 查看用户详情
- 永久封禁
- 解封

这样可以保证管理员端导航与整体结构完整，后续补用户管理接口时无需重新调整页面框架。

## Error Handling

- 登录失败：在登录页展示接口错误信息
- 非管理员登录：提示无管理员权限并留在登录页
- 视频列表加载失败：在视频管理页展示错误态
- 空数据：展示空状态
- 审核操作失败：在抽屉内展示失败提示，不关闭抽屉

## Testing Direction

第一阶段前端骨架应至少覆盖：

- 路由跳转是否正确
- 未登录拦截是否生效
- 非管理员登录是否被拒绝进入后台
- 默认首页是否为 `/videos`
- 左侧导航是否能切换视频管理与用户管理

## Implementation Boundary

用户已经明确要求当前阶段先做 `bilibili_admin_web/` 的最基础前端项目骨架，因此后续实现应优先完成：

1. 独立前端项目基础结构
2. 基础路由
3. 登录页空实现
4. 视频管理页空实现
5. 用户管理页占位实现

在未得到进一步确认前，不主动修改后端代码。
